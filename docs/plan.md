# План развития

| Приоритет | Состояние | Работа | Критерий завершения |
| --- | --- | --- | --- |
| P0 | Реализовано, проверено имитатором | Подключение к общему серверу, чтение и очередь исходной задачи | Автоматические проверки протокола проходят |
| P0 | Реализован Desktop; две реальные задачи и PDF проверены с проверочным получателем | Подключение через очередь, плагин и встроенные инструменты приложения | Настоящий Telegram, установка плагина и расписание подтверждены ручным опытом |
| P1 | Реализовано, проверено автоматически | Автоматическое обнаружение основных задач Desktop | Новая задача появляется без перезапуска; диспетчеры и подзадачи исключены; старые итоги не рассылаются |
| P1 | Реализовано | Пошаговая настройка без обязательного CLI, проверка токена, одноразовая привязка, doctor | Настройки валидируются, старый путь к CLI принимается, секрет отделён, ошибки понятны |
| P1 | Реализовано, проверено автоматически | Проверка перед первым запуском local и agent | Отказ не создаёт базу и не получает поручения; ранее проверенное подключение допускает восстановление при временном отключении |
| P1 | Реализовано, проверено автоматически | Итоги, ответы, очередь SQLite и восстановление | Две параллельные задачи сохраняют адреса, повторы не создают новые поручения |
| P1 | Реализовано, проверено автоматически | Регистрация и доставка вложений | Проверенные байты документа доставлены с привязкой к запросу |
| P1 | Требует внешней проверки | Настоящий Telegram, снимки и PDF | Выполнены пункты docs/acceptance.md |
| P1 | Реализовано, проверено через локальный HTTP | Один бот, единый узел и несколько компьютеров | Совпадающие идентификаторы задач разделены, ответ уходит только исходному компьютеру |
| P1 | Реализовано, проверено автоматически | Одноразовое подключение, отдельные ключи, отзыв | Чужие поручения отклоняются, отозванный ключ не принимается |
| P1 | Реализовано, проверено автоматически | Очереди при отключении и перезапуске, передача файлов через узел | Повторы событий не дублируют доставку, устаревший отчёт не откатывает состояние |
| P1 | Требует внешней проверки | Две физические машины, HTTPS, настоящий бот и приложение | Выполнен раздел общего бота в docs/acceptance.md |
| P2 | Реализована генерация, установка не проверена | Автоматический запуск macOS | Перезапуск после входа в систему подтверждён |
| P2 | Запланировано | Подписка на события и ограниченное чтение длинных историй | Большое число задач не требует полного перечитывания истории |
| P2 | Запланировано | Linux и Windows | Тот же сценарий проходит на каждой системе, проверены права на секреты |

После сквозной проверки зафиксировать поддержанные версии Codex и успешные сценарии. Перед обновлением протокола или выпуском версии пересматривать локальную обратную связь и повторять соответствующие проверки. Не помечать внешнюю проверку завершённой по результатам имитаторов.

Ограничения транспорта unix, отвергнутые обходы, восстановление после сбоя и
условия повторной проверки описаны в
[codex-desktop-compatibility.md](codex-desktop-compatibility.md). До выполнения
проверки протокола не выполнять первый запуск; до ручной сквозной проверки не
использовать службу постоянно и не проверять её автоматический запуск.

Для Desktop порядок установки и оставшиеся проверки: [desktop-mode.md](desktop-mode.md).
