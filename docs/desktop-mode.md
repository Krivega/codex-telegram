# Работа с настольным Codex без общего сокета

Режим `desktop` — экспериментальное подключение к исходным задачам приложения.
Для одного компьютера не нужны адрес компьютера, туннель и отдельный сетевой сервер.
Нужны установленный проект с Node.js 24+, работающая локальная служба, открытое
приложение Codex и задача-диспетчер с плагином.

Служба получает Telegram и читает только журналы явно выбранных задач. Диспетчер
забирает поручение из локальной очереди и передаёт его встроенным инструментом
`send_message_to_thread` в исходную задачу. После завершения служба отправляет
итог и зарегистрированные файлы. Отдельный App Server не запускается.

## Настройка одного компьютера

1. В каталоге проекта выполните `npm ci`.
2. В Codex попросите показать идентификаторы нужных локальных задач. Для первого
   опыта выберите две безопасные задачи. Облачные задачи и задачи другого
   компьютера здесь не подходят.
3. Создайте отдельного бота через `@BotFather` и запустите мастер:

   ```sh
   npm run setup -- --role local --home "$HOME/.config/codex-telegram-local"
   ```

   Введите токен в скрытое поле мастера, подтвердите свой Telegram. Выберите
   `desktop`, оставьте каталог журналов по умолчанию, укажите идентификаторы
   задач через запятую. `all` в этом режиме запрещён. Каталог журналов обычно
   `$HOME/.codex/sessions`; если приложение использует другой CODEX_HOME,
   укажите его подкаталог `sessions`. Внутренние настройки приложения менять не нужно.

4. Проверьте чтение и подготовьте плагин для этого компьютера:

   ```sh
   node bin/codex-telegram.mjs desktop check --home "$HOME/.config/codex-telegram-local"
   node bin/codex-telegram.mjs desktop prepare --home "$HOME/.config/codex-telegram-local"
   ```

   Последняя команда печатает абсолютный путь к готовому плагину. Его `.mcp.json`
   содержит пути к текущему Node.js, проекту и каталогу настроек, без токена.
   Команда ничего не устанавливает в приложение и не меняет его разрешения.

5. В Codex вызовите встроенный `$plugin-creator` с таким поручением, подставив
   **напечатанный абсолютный путь**:

   > Добавь готовый плагин из указанного каталога в мой личный каталог плагинов
   > и помоги установить его в Codex. Сохрани существующие skills и .mcp.json;
   > сервер MCP уже настроен. Не создавай новый пустой плагин взамен готового.

   Установите плагин из личного каталога через интерфейс Codex. Затем откройте
   отдельную новую задачу-диспетчер, чтобы она получила новые инструменты.
   Это соответствует [документированному процессу установки локальных плагинов](https://learn.chatgpt.com/docs/build-plugins).
   Команда `codex` в терминале для работы нашей службы не требуется.

6. Задача-диспетчер **не должна входить** в `codex.threadIds`. В ней напишите:

   > Используй telegram-dispatcher. Выполни один проход очереди Codex Telegram.
   > Передавай поручения только в указанные очередью исходные задачи на этом
   > компьютере; не выполняй их здесь. Не повторяй неопределённую отправку.

   При пустой очереди инструмент `desktop_claim` должен вернуть `null`.
   Если инструменты `desktop_claim`, `desktop_report`, `read_thread` или
   `send_message_to_thread` недоступны, этот вариант приложения пока не готов
   для двусторонней работы. Одно чтение журналов не подтверждает отправку.

7. Проверьте Telegram и запустите локальную службу:

   ```sh
   npm run doctor -- --home "$HOME/.config/codex-telegram-local"
   npm start -- --home "$HOME/.config/codex-telegram-local"
   ```

   В другом окне Telegram отправьте `/tasks`, ответьте на сообщение нужной
   задачи безвредным контрольным текстом. Попросите диспетчер выполнить проход.
   Проверьте ответ в исходной задаче и уведомление в Telegram. Затем таким же
   способом попросите PDF и ответьте на полученный документ.

`doctor` для Desktop проверяет журналы и локальную очередь. Он не доказывает,
что плагин установлен, диспетчер работает или приложение сейчас открыто.
Служба может получать новые уведомления без диспетчера; входящие поручения
ждут его запуска. В уведомлениях этого режима задача обозначается постоянным
идентификатором: названия из внутренних баз приложения не считываются.

Образец для настройки без мастера: [examples/desktop.config.example.json](../examples/desktop.config.example.json). Замените все идентификаторы и пути; секрет хранится отдельно.

## Автоматическая проверка очереди

После успешного ручного опыта попросите Codex **в задаче-диспетчере**:

> Настрой повторяющуюся проверку очереди Codex Telegram раз в минуту в этой
> задаче. Каждый раз используй telegram-dispatcher и передавай не больше пяти
> поручений. Не жди завершения задач. Если очередь пуста и новых ошибок нет,
> не уведомляй меня. Сообщай только о новой ошибке или необходимости моего действия.

Используется штатная [автоматизация внутри задачи Codex](https://learn.chatgpt.com/docs/automations).
Приложение и компьютер должны оставаться включёнными. Такие проходы расходуют
лимиты Codex, задержка входящего поручения может составлять минуту и больше.
Автоматизация не устанавливается командой `desktop prepare`; её первый запуск
и восстановление после сна нужно проверить отдельно. Автозапуск службы
`service install` также не запускает приложение и диспетчер.

## Один бот и два компьютера

Сохраните существующую схему `hub` + `agent`: токен бота остаётся на едином узле.
На **каждом** компьютере при `setup --role agent` выберите `desktop`, укажите
его локальные задачи, выполните `desktop prepare` с каталогом настроек этого
агента и настройте свой диспетчер. Каждый компьютер имеет отдельный ключ и
свою базу `desktop.sqlite`. Ответ в Telegram по-прежнему адресуется паре
«компьютер + задача». Эта доработка убирает необходимость сокета Codex,
но не заменяет единый узел, необходимый для одного общего бота.

## Перенос и обновление

На другом компьютере клонируйте репозиторий, выполните `npm ci`, пройдите
настройку со своими задачами и повторите `desktop prepare`. После перемещения
репозитория или смены Node.js также повторите подготовку и переустановите плагин.
Распространяется исходный репозиторий; подготовленная `.mcp.json` привязана к
конкретному компьютеру. Не публикуйте личный каталог настроек и не копируйте
один `hostId` и базу работающего агента на второй компьютер.

После изменения списка задач остановите службу и перезапустите диспетчер/MCP,
чтобы оба процесса прочитали одинаковые настройки. При обновлении плагина
используйте штатную переустановку через Plugin Creator и новую задачу-диспетчер.

## Сбой во время отправки

```sh
node bin/codex-telegram.mjs desktop status --home "$HOME/.config/codex-telegram-local"
```

- `queued` / `ready`: поручение ждёт исполнения или прохода диспетчера.
- `claimed`: диспетчер получил поручение; подтверждения пока нет.
- `accepted`: инструмент приложения подтвердил приём; запись входа ещё не найдена.
- `uncertain`: подтверждения нет; автоматическая повторная выдача запрещена.

При чтении входной метки поручения из журнала соответствующая запись снимается
с этой очереди. Состояние выполнения и доставка видны обычной командой `status`.
Если диспетчер завершился после получения поручения, запись остаётся `claimed`:
истечение времени само по себе не разрешает повтор. Откройте исходную задачу
и проверьте приём. Если он подтверждён журналом, служба восстановится сама.
Если приёма нет, автоматического повтора и команды сброса сейчас нет; запись
блокирует последующие поручения этой задачи до разбирательства разработчиком.
Остальные задачи продолжают работать. Не редактируйте SQLite вручную.

Не подтверждайте системные разрешения из диспетчера. Если задача начала работу
между проверкой состояния и отправкой, инструмент приложения может направить
сообщение в активный ход. Проверка занятости уменьшает это окно, но не даёт
атомарной гарантии; перед первой постоянной установкой проверьте этот сценарий.

## Границы совместимости и обратная связь

Подтверждён ручной опыт на macOS с ChatGPT 26.908.40834 (сборка 8881): две исходные
задачи, контрольные ответы, настоящий одностраничный PDF и его передача в
проверочный получатель вместо Telegram. MCP проверен отдельно, в том числе
запуском отдельного процесса через stdio. Установка плагина в приложение,
его работа по расписанию, настоящий бот, снимки страницы и два физических
компьютера ещё не проверены. Подробности — [acceptance.md](acceptance.md).

Чтение журналов экспериментальное. Служба проверяет `session_meta.id`, события
`task_started`, `item_completed` и `task_complete`; читает только законченные
строки, а затем только дописанные байты. Некорректная запись останавливает чтение
задачи без раскрытия её содержимого. Архивированные и удалённые журналы не
поддерживаются. Одна строка ограничена 32 МиБ; общая история итогов пока не очищается.
Состояния ожидания разрешения не извлекаются из журнала: их проверяет диспетчер
перед отправкой, а решение остаётся в исходной задаче.

После обновлений Codex повторяйте опыт на двух задачах. В Telegram используйте
`/feedback описание`, указав ожидаемый и фактический результат без секретов.
Команда `feedback` показывает сохранённые замечания. Успешные версии приложения
и сценарии фиксируйте в acceptance.md перед изменением правил совместимости.
