# Правила разработки

- Основная логика находится в Coordinator и CodexWorker; Bridge сохраняет однокомпьютерный режим; протоколы изолированы интерфейсами CodexPort и TelegramPort.
- Новые входящие сообщения всегда адресуются по постоянной привязке Telegram с идентификатором компьютера, а не по названию или последней активной задаче.
- Не создавать, не копировать и не возобновлять чужую задачу для обхода недоступного общего сервера.
- Не расширять разрешения Codex и не подтверждать системные запросы от имени владельца.
- Не добавлять токены, личные настройки, SQLite, журналы и результаты в Git или диагностические сообщения.
- Изменения доставки должны сохранять обработку повторов, восстановление и различие между отказом и неопределённым результатом.
- Проверять `npm run check`. Изменения протокола сверять с документацией и схемами конкретной версии Codex.
- Различать тесты на имитаторах и живую проверку приложения, Telegram, снимков и PDF. Обновлять docs/acceptance.md только по фактическим результатам.
- Просматривать сохранённые через /feedback замечания при планировании выпуска; документировать успешные сценарии и пересматривать правила при изменении протоколов.
- Токен Telegram принадлежит только единому узлу. Компьютеры подключаются исходящими соединениями с отдельными отзываемыми ключами.
- Повтор между компьютером и узлом безопасен по постоянному ключу события; не переносить это допущение на отправку в Telegram или неопределённый запрос Codex.
- Для сетевых изменений проверять два независимых хранилища компьютеров, совпадающие идентификаторы задач, отключение, перезапуск и отзыв ключа.
