# Codex Telegram

Личная служба для получения результатов Codex в Telegram, ответов в исходную задачу и доставки созданных PDF и изображений.

**Версия 0.1.0 — начало разработки.** Основная логика и транспорт проверены автоматическими тестами. Работа с текущим настольным приложением и настоящим Telegram-ботом ещё не подтверждена. Программа требует доступный общий сервер Codex, обслуживающий нужные задачи. Наличие Codex CLI само по себе недостаточно.

## Быстрый запуск

Нужны Node.js 24 или новее, Codex CLI с `app-server proxy` и операциями очереди, отдельный Telegram-бот и доступ к задачам на общем сервере Codex. У приложения должен сохраняться доступ к рабочим файлам и инструментам создания результатов.

В каталоге проекта:

```sh
npm ci
npm run setup
npm run doctor
npm start
```

Настройка задаёт несколько вопросов:

1. Токен отдельного бота, созданного через `@BotFather`. Ввод скрыт.
2. Привязка личного Telegram: программа показывает ссылку с одноразовым кодом; откройте её и нажмите «Запустить».
3. Путь к Codex и адрес общего локального сокета.
4. Все основные задачи или выбранные идентификаторы, интервал проверки.

Настройки сохраняются вне репозитория:

- macOS: `~/Library/Application Support/codex-telegram`;
- Linux: `$XDG_CONFIG_HOME/codex-telegram` либо `~/.config/codex-telegram`;
- Windows: `%LOCALAPPDATA%/codex-telegram`.

Другой каталог задаётся через `CODEX_TELEGRAM_HOME` либо аргумент `--home /absolute/path`. Сохранённый `hostId` идентифицирует конкретную установку. На Linux и Windows основной код пока не проверен.

## Подключение к Codex

Служба подключается через `codex app-server proxy --sock <путь>`. Она не запускает отдельный сервер, не копирует историю и не создаёт новую задачу вместо исходной.

Путь по умолчанию: `$CODEX_HOME/app-server-control/app-server-control.sock`, где обычный `CODEX_HOME` — `~/.codex`.

`doctor` проверяет чтение списка задач, истории и очереди. Если сокет отсутствует, сначала нужно выяснить, предоставляет ли ваша версия приложения общий сервер и как подключиться к нему. Запуск произвольного `codex app-server` не доказывает связь с открытыми чатами. Проверка выполняется по [инструкции приёмки](docs/acceptance.md).

Отправка разрешена только в задачу, уже загруженную этим сервером и сообщающую `canAcceptDirectInput: true`. Задачу, доступную только как сохранённая история, нужно открыть в её исходном клиенте. Неподдерживаемая версия протокола приводит к понятной ошибке, а не к обходу через отдельный `exec resume`.

## Переписка в Telegram

После завершения выполнения приходит итоговый ответ Codex. Длинный ответ сокращается до настроенного объёма; это сокращение текста, а не дополнительный пересказ моделью. Исторические завершения до запуска не рассылаются. Окончание ответа означает окончание выполнения, а не независимое подтверждение результата задачи.

Нажмите «Ответить» на уведомлении и напишите, например:

> Сделай снимок мобильной версии и пришли его сюда.

> Подготовь PDF с результатами и оставшимися вопросами.

Поручение попадёт в ту же задачу. Если задача занята, оно ожидает в очереди. Настройки модели, права доступа и решения по системным запросам служба не меняет. При ожидании разрешения или системного уточнения поступает уведомление с предложением открыть Codex.

Команды бота:

| Команда | Действие |
| --- | --- |
| `/tasks` | Показать до 20 доступных задач; на каждое сообщение можно ответить |
| `/full` | Получить полный итог; отправляется ответом на конкретное уведомление |
| `/status` | Посмотреть незавершённые поручения и проблемные доставки |
| `/feedback текст` | Сохранить замечание локально, с привязкой к сообщению |
| `/help` | Показать подсказку |

Первая версия принимает текст в личном чате владельца с ботом. Входящие голосовые сообщения, фотографии и групповые чаты не поддерживаются.

## PDF и изображения

К передаваемому поручению добавляется инструкция для Codex: сохранить предназначенные для отправки файлы в каталог конкретного поручения и создать `manifest.json`:

```json
{
  "files": [
    { "path": "report.pdf", "name": "Отчёт.pdf" },
    { "path": "mobile.png", "name": "Мобильная версия.png" }
  ]
}
```

Результаты находятся в `<каталог настроек>/artifacts/<идентификатор поручения>`. Если разрешения Codex не позволяют туда писать, потребуется разрешение в исходном приложении. Служба не расширяет доступ самостоятельно.

После завершения связанного выполнения служба проверяет список, границы каталога, размер, сигнатуру формата и контрольную сумму. PDF, PNG, JPEG и WebP отправляются документами, чтобы сохранять исходные байты. Ссылки на файлы из обычного текста не загружаются автоматически. Ответ непосредственно на документ тоже связан с исходной задачей.

Служба не создаёт изображения и PDF сама: это поручение Codex и его доступным инструментам. Проверка сигнатуры не заменяет проверку содержимого PDF или качества снимка.

## Настройки

`npm run setup` можно повторить при остановленной службе. Уже привязанный бот сохраняется. Для другого бота используйте отдельный каталог настроек.

В `config.json` находятся параметры из [примера](config.example.json). Основные настройки:

| Параметр | Значение по умолчанию |
| --- | --- |
| `codex.threadIds` | `[]`: все основные задачи; идентификаторы ограничивают список |
| `codex.pollIntervalMs` | 5000 мс |
| `notifications.maxTextLength` | 3200 единиц UTF-16, без разрыва символов |
| `artifacts.maxFileBytes` | 20 МиБ на вложение |
| `artifacts.maxFiles` | 5 вложений на поручение |

Изменения применяются после перезапуска. Токен находится только в `secrets.json` с правами `0600`; на системах Unix каталог создаётся с `0700`. Альтернатива — переменная `TELEGRAM_BOT_TOKEN`. Это локальное хранение с ограничением доступа, не шифрование хранилища. На Windows нужно отдельно обеспечить доступ к каталогу только владельцу.

Проверить настройки без вывода токена:

```sh
node bin/codex-telegram.mjs config
```

## Автоматический запуск на macOS

Сначала пройдите `doctor` и сквозную проверку. Для службы задайте абсолютный путь `codex.executable`: его показывает `command -v codex`. Токен должен быть сохранён мастером настройки.

```sh
node bin/codex-telegram.mjs service install
node bin/codex-telegram.mjs service uninstall
```

Устанавливается пользовательская служба `launchd`. Удаление автоматического запуска сохраняет настройки. После смены пути Node.js или перемещения проекта переустановите службу. Mac должен оставаться включённым; закрытый или спящий компьютер не выполняет поручения.

## Восстановление после сбоев

SQLite сохраняет входящие обновления до подтверждения Telegram, привязки сообщений, очередь поручений и доставки. Повтор входящего обновления не создаёт второе поручение. После разрыва связи принятый запрос сверяется по постоянному `clientUserMessageId` с очередью и историей Codex.

У Telegram нет универсальной гарантии однократной отправки: если ответ потерян после приёма сообщения сервером, результат становится неопределённым. Программа не повторяет такую отправку без проверки владельцем.

```sh
node bin/codex-telegram.mjs status
# После проверки Telegram, при остановленной службе:
node bin/codex-telegram.mjs retry --delivery 17 --confirm-duplicate-risk
```

Только явно отклонённые Telegram запросы с `retry_after` автоматически возвращаются в очередь. Неопределённое поручение Codex повторно не запускается: сначала выполняется сверка очереди и истории. Если доказательство приёма не появилось, владелец проверяет исходную задачу и решает, отправлять ли новое поручение.

База, вложения и замечания сохраняются локально без автоматического удаления. Для резервного копирования остановите службу и копируйте весь каталог состояния. При долгом отключении получение ещё не сохранённых обновлений ограничено сроком хранения Telegram. История без временных отметок не обеспечивает полного восстановления пропущенных завершений: такие записи не рассылаются задним числом.

## Перенос и совместная разработка

Клонируйте репозиторий на другом компьютере, выполните `npm ci` и настройте собственную установку. Каталог настроек, SQLite, токены и результаты в Git не включаются. Передача исходников не передаёт доступ к вашему Codex или боту.

Перенос старых задач Codex не реализован. Для сохранения прежней переписки нужны сами задачи, рабочие файлы и отдельная проверка идентификаторов. База привязана к `hostId` и владельцу бота; случайное использование с другой установкой блокируется. Две работающие копии с одним ботом не допускаются; локальная блокировка защищает один каталог, а разные компьютеры нужно координировать самостоятельно.

Проверки разработчика:

```sh
npm ci
npm run check
```

Рабочие зависимости отсутствуют: используются стандартные возможности Node.js. Для разработки установлены TypeScript и типы Node.js, точные версии закреплены в `package-lock.json`. SQLite в проверенной версии Node.js сообщает об экспериментальном статусе.
